개념 이해

구글 앱스크립트는 구글 서비스에 붙이는 작은 프로그램입니다

구글 앱스크립트(Google Apps Script, 줄여서 GAS)는 구글 시트, 문서, 설문지, 지메일 같은 구글 서비스를 코드로 움직일 수 있게 해 주는 도구입니다. 별도 프로그램을 설치할 필요 없이 브라우저에서 바로 쓰고, 무료입니다.

엑셀 매크로와 비슷하지만 더 멀리 갑니다

엑셀 매크로가 파일 안의 반복 작업을 자동화한다면, 앱스크립트는 여기에 더해 인터넷 너머와 대화할 수 있습니다. 오늘 만드는 시스템에서 앱스크립트가 하는 일은 세 가지입니다.

  1. 시트 읽기: [문항설정] 탭의 문항을 읽어 웹페이지에 넘겨줍니다.
  2. 외부 AI 부르기: 학생 답변을 제미나이 API로 보내고 피드백을 받아옵니다.
  3. 시트 쓰기: 답변, 피드백, 생기부 초안을 [학생답안] 탭에 기록합니다.

API는 프로그램끼리 대화하는 창구입니다

우리가 제미나이 웹사이트에서 채팅을 하듯, 프로그램도 제미나이에게 질문을 보낼 수 있습니다. 이때 프로그램이 이용하는 창구가 API입니다.

채팅과 API의 차이

채팅 화면

사람이 직접 질문을 입력하고 답을 읽습니다. 학생 30명의 답변이라면 30번 복사해서 붙여넣어야 합니다.

API

앱스크립트가 대신 질문을 보내고 답을 받습니다. 학생이 제출할 때마다 자동으로 일어나고, 결과는 시트에 바로 기록됩니다.

API 키는 출입증입니다

API를 쓰려면 "누가 요청하는지" 알려주는 API 키가 필요합니다. 긴 영문과 숫자로 된 문자열이고, 구글 AI 스튜디오에서 무료로 발급받습니다.

API 키는 비밀번호처럼 다루세요. 키가 다른 사람에게 알려지면 그 사람이 선생님 이름으로 API를 쓸 수 있습니다. 그래서 오늘은 키를 코드에 직접 쓰지 않고, 앱스크립트의 스크립트 속성이라는 별도 보관함에 넣습니다. 코드를 다른 선생님과 공유해도 키는 함께 퍼지지 않습니다.

무료 사용량에는 한도가 있습니다

무료 API는 1분에 보낼 수 있는 요청 수와 하루 요청 수에 한도가 있습니다. 한 반 학생이 동시에 제출하면 잠시 한도에 걸릴 수 있으니, 수업에서는 모둠별로 나눠 제출하게 하는 식으로 운영하면 안정적입니다. 정확한 한도는 모델마다 다르고 바뀔 수 있으니 구글 AI 스튜디오에서 확인하세요.

개념 이해

배포는 앱스크립트에 인터넷 주소를 붙이는 일입니다

앱스크립트 코드는 그대로 두면 시트 안에서만 돌아갑니다. 학생용 웹페이지가 앱스크립트에 말을 걸려면 인터넷 주소가 필요한데, 이 주소를 만드는 과정이 웹 앱 배포입니다.

배포가 끝나면 https://script.google.com/macros/s/…/exec 모양의 URL이 생깁니다. 이 URL이 앱스크립트의 "전화번호"이고, 학생용 웹페이지는 이 번호로 전화를 겁니다.

순서가 중요한 이유웹페이지를 만들려면 앱스크립트의 URL이 있어야 하고, URL은 배포를 해야 생깁니다. 그래서 이 연수는 앱스크립트를 먼저 완성하고 배포한 뒤, 그 URL을 넣어 웹페이지를 만드는 순서로 진행합니다.

  1. 브라우저 주소창에 sheets.new를 입력하고 Enter를 누릅니다. 빈 구글 시트가 바로 열립니다. (구글 드라이브에서 새로 만들기 → Google 스프레드시트로 만들어도 됩니다.)
  2. 왼쪽 위 제목 없는 스프레드시트를 눌러 이름을 바꿉니다. 예: AI피드백_1학년_기술
  3. 시트는 비워 둡니다. [문항설정]과 [학생답안] 탭은 나중에 앱스크립트가 자동으로 만들어 줍니다.
이름 짓기 팁 과목, 학년, 단원을 넣어 두면 나중에 여러 개를 만들어도 헷갈리지 않습니다. 이 시스템은 단원마다 시트를 하나씩 복사해서 쓰기 좋습니다.
탭을 직접 만들지 않는 이유코드가 찾는 탭 이름은 정확히 문항설정, 학생답안입니다. 띄어쓰기 하나만 달라도 코드가 탭을 찾지 못합니다. 코드가 알아서 만들게 두면 이런 실수를 피할 수 있습니다.

[전체 구조]
- 학생은 별도의 HTML 웹페이지에서 답을 쓰고 제출한다.
- 이 앱스크립트는 웹 앱으로 배포되어, HTML과 fetch로 통신한다.

[요구사항]
1. 구글 시트의 [문항설정] 탭(A열 번호, B열 문항제목, C열 문항내용)에서 문항을 읽어, doGet에서 action=getQuestions 요청이 오면 JSON으로 돌려준다. 탭이 없으면 예시 문항 2개와 함께 자동으로 만든다.
2. doPost로 학번(studentId), 별명(nickname), 문항별 답안 목록(answers)을 JSON으로 받는다. HTML이 Content-Type을 text/plain으로 보내도 e.postData.contents를 JSON으로 읽을 수 있게 한다.
3. 받은 답안을 Gemini API(모델 이름은 상수로 따로 빼 둘 것)에 보내서, 학생용 개별 피드백(200자 내외, 존댓말, 격려와 보완점)과 교사용 생활기록부 관찰 초안(100자 내외, 교사 업무 문체)을 JSON 형식으로 받는다.
4. [학생답안] 탭에 타임스탬프, 학번, 별명, 문항/답안, 개별피드백, 생기부초안을 한 줄씩 기록한다. 탭이 없으면 제목 행과 함께 자동으로 만든다.
5. 학생에게는 개별 피드백만 돌려주고, 생기부 초안은 돌려주지 않는다.
6. API 키는 코드에 쓰지 말고, 스크립트 속성 GEMINI_API_KEY에서 읽는다.
7. 설정이 제대로 됐는지 확인하는 checkSetup 함수를 만든다. API 키 저장 여부, 제미나이 호출 성공 여부, 등록된 문항 수를 실행 로그에 보여준다.
8. 오류가 나면 학생 화면에 보여줄 수 있게 status와 message를 담은 JSON으로 돌려준다.

[작성 방식]
- 코딩을 모르는 교사가 읽을 수 있게, 코드 맨 위에 설정 방법(스크립트 속성 저장, 웹 앱 배포, checkSetup 실행)을 단계별 한국어 주석으로 적어 줘.

- 코드는 하나의 Code.gs 파일로 완성된 형태로 줘.

function doGet(e) {

// [문항설정] 탭에서 문항 목록을 읽어오기
// 시트 구조: A열=번호, B열=문항제목, C열=문항내용
function getQuestionList_() {
  const ss = SpreadsheetApp.getActiveSpreadsheet();
  let sheet = ss.getSheetByName(QUESTIONS_SHEET_NAME);

  // 탭이 없으면 예시와 함께 자동으로 만들어줌
  if (!sheet) {
    sheet = ss.insertSheet(QUESTIONS_SHEET_NAME);
    sheet.appendRow(['번호', '문항제목', '문항내용']);
    sheet.appendRow([1, '문항1 제목', '여기에 문항1의 실제 내용을 입력하세요']);
    sheet.appendRow([2, '문항2 제목', '여기에 문항2의 실제 내용을 입력하세요']);
  }

  const values = sheet.getRange(2, 1, Math.max(sheet.getLastRow() - 1, 0), 3).getValues();
  return values
    .filter(row => row[1] && row[1].toString().trim() !== '')  // 문항제목이 빈 줄은 제외
    .map(row => ({
      no: row[0],
      title: row[1].toString().trim(),
      content: row[2] ? row[2].toString().trim() : ''
    }));
}

// [학생답안] 탭에 결과 저장하기
function saveToAnswerSheet_(data, aiResult) {
  const ss = SpreadsheetApp.getActiveSpreadsheet();
  let sheet = ss.getSheetByName(ANSWERS_SHEET_NAME);
  if (!sheet) {
    sheet = ss.insertSheet(ANSWERS_SHEET_NAME);
    sheet.appendRow(['타임스탬프', '학번', '별명', '문항/답안(JSON)', '개별피드백', '생기부초안']);
  }
  sheet.appendRow([
    new Date(),
    data.studentId || '',
    data.nickname || '',
    JSON.stringify(data.answers || []),
    aiResult.feedback,
    aiResult.recordDraft
  ]);
}

// Gemini API 호출
function callGemini_(prompt) {
  const apiKey = PropertiesService.getScriptProperties().getProperty('GEMINI_API_KEY');
  if (!apiKey) {
    throw new Error('스크립트 속성에 GEMINI_API_KEY가 설정되어 있지 않습니다. 코드 상단의 [2단계] 설명을 참고하세요.');
  }

  const url = `https://generativelanguage.googleapis.com/v1beta/models/${GEMINI_MODEL}:generateContent?key=${apiKey}`;

  const payload = {
    contents: [{ parts: [{ text: prompt }] }],
    generationConfig: { responseMimeType: 'application/json' }
  };

  const options = {
    method: 'post',
    contentType: 'application/json',
    payload: JSON.stringify(payload),
    muteHttpExceptions: true
  };

  const response = UrlFetchApp.fetch(url, options);
  const json = JSON.parse(response.getContentText());

  if (json.error) {
    throw new Error('Gemini API 오류: ' + json.error.message);
  }

  const rawText = json.candidates[0].content.parts[0].text;
  const parsed = JSON.parse(rawText);

  return {
    feedback: parsed.feedback || '',
    recordDraft: parsed.recordDraft || ''
  };
}

// Gemini에게 보낼 질문(프롬프트) 만들기

    .map((a, i) => `문항${i + 1}: ${a.question}\n학생답안: ${a.answer}`)
    .join('\n\n');

  return `

요청문에 꼭 들어가야 할 것

  • 웹 앱 URL과, 그 URL이 어떤 요청에 어떻게 응답하는지(GET으로 문항, POST로 피드백)

  • 제출할 때 Content-Type을 application/json으로 보내지 않을 것: 헤더를 아예 지정하지 않거나 text/plain으로 보내야 합니다. application/json으로 보내면 브라우저 보안 규칙(CORS) 때문에 제출이 실패합니다.
  • 원하는 화면 분위기와 안내 문구
HTML 요청 프롬프트
학생이 답안을 제출하고 AI 피드백을 받는 웹페이지를 HTML 파일 하나로 만들어 줘. CSS와 자바스크립트도 모두 한 파일 안에 넣어 줘.

[연결할 앱스크립트 웹 앱 URL]
여기에_웹앱_URL_붙여넣기

[앱스크립트의 동작]
- GET 요청: URL?action=getQuestions → {"status":"success","questions":[{"no":1,"title":"문항제목","content":"문항내용"}]}
- POST 요청: 본문에 {"studentId":"학번","nickname":"별명","answers":[{"question":"문항","answer":"답"}]} 를 JSON 문자열로 보냄 → {"status":"success","feedback":"피드백"} 또는 {"status":"error","message":"오류 내용"}

[기능]
1. 페이지가 열리면 문항 목록을 불러와 문항마다 '번호. 제목', 내용, 답 입력칸을 보여 줘. AI에게 보낼 question에는 '번호. 제목 - 내용'을 담아 줘.
2. 맨 위에 학번과 별명 입력칸을 둬. 이름은 받지 않아.
3. 제출 버튼을 누르면 빈칸이 없는지 확인한 뒤 POST로 보내. 이때 CORS 오류를 피하도록 headers는 따로 지정하지 말고 body에 JSON 문자열만 담아 보내 줘. (application/json 헤더는 쓰지 마.)

내 컴퓨터의 파일은 학생이 열 수 없습니다. 학생에게 링크를 주려면 HTML 파일을 인터넷에 올려야 합니다. 무료로 쓸 수 있는 방법은 여러 가지입니다.

방법특징
Netlify Drop사이트에 HTML 파일이 든 폴더를 끌어다 놓으면 바로 주소가 생깁니다. 가장 간단합니다.
GitHub Pages깃허브 계정이 있다면 저장소에 올려 무료로 공개할 수 있습니다. 파일을 여러 개 관리하기 좋습니다.
생성형 AI의 공유 기능일부 생성형 AI는 만든 웹페이지를 링크로 공유하는 기능을 제공합니다.
인터넷에 올릴 때는 파일 이름을 index.html로 Netlify나 GitHub Pages는 폴더 안의 index.html을 첫 화면으로 보여 줍니다. student.html 그대로 올리면 받은 주소 끝에 /student.html을 붙여야 열립니다. 올리기 전에 파일 이름을 index.html로 바꾸면 주소가 간단해집니다.

만들어진 링크를 구글 클래스룸, 패들렛, QR 코드 등으로 학생에게 나눠 주면 됩니다.

API 키가 HTML에 없다는 점이 중요합니다. HTML 파일에는 앱스크립트 URL만 들어 있고, 제미나이 API 키는 앱스크립트의 스크립트 속성 안에 숨어 있습니다. 그래서 누구나 볼 수 있는 인터넷에 HTML을 올려도 키가 드러나지 않습니다. 13단계에서 키를 스크립트 속성에 넣은 이유가 여기서 빛을 봅니다. 다만 웹 앱 URL을 아는 사람은 누구나 답안을 제출할 수 있으니, 링크는 우리 반 학생에게만 나눠 주세요.

3성찰오늘 수업에서 가장 어려웠던 점과 그 이유를 써 보세요.
  1. 시트 아래쪽의 [문항설정] 탭을 엽니다.
  2. 예시 문항 두 줄을 지우거나 덮어쓰고, 수업에 쓸 문항을 적습니다. 1행(제목 행)은 그대로 둡니다.
  3. 번호(A열)도 꼭 채웁니다. 웹페이지에는 "1. 개념 설명"처럼 이 번호가 그대로 붙어 나오고, AI에게도 "1. 개념 설명 - 문항내용" 형태로 전달됩니다. 번호를 비우면 제목 앞에 점(.)만 남습니다.
  4. 문항제목(B열)이 비어 있는 줄은 웹페이지에 나오지 않습니다. 문항내용(C열)은 비워도 되지만, 채워 두면 학생과 AI 모두 무엇을 써야 할지 더 분명해집니다.
문항에 < > 기호는 쓰지 마세요. 예시 HTML은 시트의 문항 글을 그대로 화면에 넣기 때문에, < > 같은 기호가 있으면 글자 일부가 사라져 보일 수 있습니다. "A가 B보다 크다"처럼 말로 풀어 쓰세요.
문항을 모두 지우면 웹페이지에 "문항을 불러오지 못했습니다. GAS_URL 설정 또는 시트의 [문항설정] 탭을 확인해주세요."가 나오고 제출 버튼이 눌리지 않습니다. 최소 한 줄은 남겨 두세요.
피드백이 좋아지는 문항 쓰기 "설명해 보세요", "근거를 들어 써 보세요"처럼 무엇을 써야 하는지 분명한 문항일수록 AI 피드백도 구체적으로 나옵니다. 문항내용에 평가 기준을 한 줄 덧붙여도 좋습니다.
문항을 시트에서 관리하는 이유수업마다 코드를 고치고 다시 배포하는 것은 번거롭고 실수가 생기기 쉽습니다. 시트만 고치면 되니, 한 번 만든 시스템을 여러 단원과 과목에 계속 재사용할 수 있습니다. 문항만 바꿀 때는 앱스크립트를 다시 배포할 필요도, HTML 파일을 고칠 필요도 없습니다.

이런 메시지가 나오면원인해결
"스크립트 속성에 GEMINI_API_KEY가 설정되어 있지 않습니다"API 키 미설정 또는 속성 이름 오타13단계로 돌아가 속성 이름과 값을 확인합니다.

"API key not valid"키를 잘못 복사했거나 키가 삭제됨구글 AI 스튜디오에서 키를 다시 복사해 스크립트 속성 값을 고칩니다.

"Cannot read properties of undefined"AI가 답변을 만들지 않음. 학생 답에 부적절한 표현이 있어 안전 필터에 걸린 경우가 많음해당 학생의 답안을 확인하고, 표현을 고쳐 다시 제출하게 합니다.
제출은 됐는데 피드백 칸이 비어 있음AI가 feedback 항목을 빠뜨림다시 제출합니다. 반복되면 buildPrompt_의 JSON 예시가 코드의 이름(feedback, recordDraft)과 같은지 확인합니다.

코드를 고쳤는데 피드백이 그대로임새 버전으로 배포하지 않음배포 → 배포 관리 → 수정 → 버전: 새 버전 → 배포를 합니다.

첫 제출이 들어오면 [학생답안] 탭이 자동으로 생기고, 제출할 때마다 한 줄씩 쌓입니다.

타임스탬프학번별명문항/답안(JSON)개별피드백생기부초안

기록과 생기부 초안에서 생길 수 있는 문제

피드백 단계에서 오류가 나면 답안도 저장되지 않습니다. 이 코드는 제미나이에게 피드백을 받은 다음에 시트에 기록하기 때문에, 한도 초과 등으로 오류가 나면 그 제출은 시트에 남지 않습니다. 학생 화면에 오류가 떴다면 반드시 다시 제출하게 하세요. 답안만이라도 꼭 남기고 싶다면 생성형 AI에게 "제미나이 오류가 나도 답안은 먼저 [학생답안] 탭에 저장되도록 Code.gs를 고쳐 줘"라고 요청할 수 있습니다.
이런 증상이면원인해결
학생은 제출했다는데 시트에 기록이 없음피드백 단계에서 오류가 나 저장되지 않음학생 화면에 오류가 있었는지 확인하고 다시 제출하게 합니다. 21단계의 피드백 문제를 먼저 해결합니다.
[학생답안] 탭이 두 개가 되거나 새 탭이 생김탭 이름을 바꿈코드는 정확히 학생답안이라는 이름의 탭을 찾습니다. 탭 이름을 바꾸지 말고, 정리가 필요하면 별도 탭에 복사해서 작업합니다.
같은 학생의 기록이 여러 줄 있음학생이 여러 번 제출함타임스탬프가 가장 늦은 줄을 최종 답안으로 봅니다. 학번 열에 필터를 걸면 쉽게 찾을 수 있습니다.
생기부초안 칸이 비어 있음AI가 recordDraft 항목을 빠뜨림드문 경우이므로 그 학생만 다시 제출하게 하거나, 교사가 직접 작성합니다. 자주 반복되면 buildPrompt_의 JSON 예시를 확인합니다.
초안이 어느 학생에게나 쓸 수 있는 일반적인 문장임답변이 짧거나 AI에게 작성 기준이 없음buildPrompt_에 "학생 답변에 나타난 구체적인 내용과 표현을 근거로, 관찰 가능한 사실 중심으로 써 줘"를 추가하고 새 버전으로 배포합니다.
초안에 과장된 표현이나 기재할 수 없는 내용이 들어감AI가 학교생활기록부 기재요령을 모름교사가 기재요령에 맞게 반드시 고쳐 씁니다. 요청문에 "과장된 수식어를 쓰지 말고, 학교생활기록부 기재요령에 맞는 문체로 써 줘"를 넣으면 줄어듭니다.
문항/답안 열이 읽기 어려움여러 문항을 JSON 한 칸에 모아 저장함그대로 두어도 AI 분석에는 문제가 없습니다. 사람이 보기 편하게 문항별 열로 나누고 싶다면 생성형 AI에게 코드 수정을 요청합니다.
활용 팁 학번 열로 정렬하거나 필터를 걸면 한 학생의 여러 차시 기록을 모아 볼 수 있습니다. 한 학기 동안 쌓인 기록은 학생의 성장을 보여 주는 자료가 됩니다. 시트에는 학생 답변이 모여 있으니, 공유 설정은 선생님 혼자 보는 상태로 유지하세요.
